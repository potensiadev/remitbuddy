## 1. 개요

### 1.1 프로젝트 배경

RemitBuddy는 외국인 근로자 및 유학생을 대상으로 하는 해외송금 비교 서비스입니다. 현재 n8n 기반의 블로그 자동화 시스템을 운영 중이나, 다음과 같은 치명적인 문제점이 식별되었습니다.

### 1.2 현재 문제점 요약

| 카테고리 | 문제점 | 심각도 |
|----------|--------|--------|
| 품질 관리 | 검증 실패해도 콘텐츠가 업로드됨 | 🔴 Critical |
| 데이터 신뢰성 | AI 환각으로 인한 부정확한 금융 정보 | 🔴 Critical |
| 데이터 신뢰성 | 실시간 뉴스/환율 데이터 부재 | 🔴 Critical |
| 시스템 안정성 | Claude API 단일 장애점 | 🟡 High |
| 시스템 안정성 | 재시도 로직 불충분 (1회만) | 🟡 High |
| SEO 효과성 | 데이터 기반 키워드 선정 아님 | 🟡 High |
| 운영 효율성 | 성과 피드백 루프 없음 | 🟡 High |
| 유지보수성 | 한국어/영어 로직 중복 | 🟢 Medium |
| 거버넌스 | 버전 관리 없음 | 🟢 Medium |

### 1.3 프로젝트 목표

1. **콘텐츠 품질 보장**: 검증 실패 시 발행 차단
2. **데이터 정확성 확보**: 실시간 환율/뉴스 데이터 연동
3. **시스템 안정성 강화**: Fallback LLM + 강화된 재시도 로직
4. **SEO 효과 극대화**: 데이터 기반 키워드 선정 + 성과 학습
5. **운영 효율성 향상**: EN→KO 통합 파이프라인 + 버전 관리

## 2. 현재 시스템 분석

### 2.1 현재 워크플로우 구조

```
Schedule Trigger (Mon/Thu 9:00 AM KST)
    │
    ├─→ Claude: News Collector ─┬─→ Wait for All Data
    └─→ Read Notion Published ──┘
                                 │
                                 ↓
                      Process News & Notion Data
                                 │
                                 ↓
                      Claude: Topic Selector
                                 │
                                 ↓
                      Parse Topic Selection
                    ┌──────────┴──────────┐
                    ↓                     ↓
         Claude: Blog Writer KO    Claude: Blog Writer EN
                    ↓                     ↓
         Parse & Convert KO        Parse & Convert EN
                    ↓                     ↓
         Validate KO Blog          Validate EN Blog
                    ↓                     ↓
         Notion Upload KO          Notion Upload EN
                    ↓                     ↓
         Append Remaining KO       Append Remaining EN
                    └──────────┬──────────┘
                               ↓
                      Wait for Uploads
                               ↓
                      Compile Report
                               ↓
                      Slack Notification

[Error Handling]
Error Trigger → Slack Error Alert → Wait 10 Min → Retry → Check → Slack Result
```

### 2.3 현재 검증 항목 (Validate Node)

| 카테고리 | 검증 항목 |
|----------|----------|
| Content Structure | Word count (1500-2500), H1 count (1), H2 count (3-5), Conclusion, FAQ (3+), CTA (RemitBuddy) |
| SEO | Keyword in title, Keyword in first paragraph, Meta description (100-160), Title length (≤60), Slug format |
| Notion Blocks | Lists, Callouts, Toggles, Emojis |
| Readability | Paragraph length, Korean honorifics, Bilingual terms, Numerical examples |
| Metadata | Tags count (3-5), Category |

## 4. 상세 요구사항

### 4.1 REQ-001: 검증 게이트 (Validation Gate)

#### 4.1.1 개요

| 항목 | 내용 |
|------|------|
| 요구사항 ID | REQ-001 |
| 우선순위 | 🔴 P0 (Critical) |
| 복잡도 | Low |
| 예상 공수 | 2시간 |

#### 4.1.2 현재 동작

```
Validate KO Blog → Notion Upload KO (무조건 진행)
Validate EN Blog → Notion Upload EN (무조건 진행)
```

- 검증 결과와 무관하게 항상 Notion에 업로드됨
- 검증 실패 정보는 최종 리포트에만 포함

#### 4.1.3 목표 동작

```
Validate KO Blog ─┬─→ IF (validation_passed === true) → Notion Upload KO
                  └─→ IF (validation_passed === false) → Slack: Validation Failed → END

Validate EN Blog ─┬─→ IF (validation_passed === true) → Notion Upload EN
                  └─→ IF (validation_passed === false) → Slack: Validation Failed → END
```

- 검증 실패 시 업로드 차단
- 검증 실패 사유를 Slack으로 즉시 알림
- 워크플로우 종료 (다음 스케줄에 재시도)

#### 4.1.4 구현 상세

**추가 노드:**

| 노드명 | 유형 | 위치 |
|--------|------|------|
| IF Validation KO | IF | Validate KO Blog → Notion Upload KO 사이 |
| IF Validation EN | IF | Validate EN Blog → Notion Upload EN 사이 |
| Slack: Validation Failed KO | HTTP Request | IF 분기의 false 경로 |
| Slack: Validation Failed EN | HTTP Request | IF 분기의 false 경로 |

**IF 조건:**


### 4.2 REQ-002: Gemini API 연동 (실시간 데이터)

#### 4.2.1 개요

| 항목 | 내용 |
|------|------|
| 요구사항 ID | REQ-002 |
| 우선순위 | 🔴 P0 (Critical) |
| 복잡도 | Medium |
| 예상 공수 | 4시간 |

#### 4.2.2 문제점

- 현재 Claude News Collector는 학습 데이터 기반 추론
- 실제 실시간 환율/뉴스 데이터가 아님
- 금융 정보 부정확성 → 신뢰도 하락 + 법적 리스크

#### 4.2.3 해결 방안

Google Gemini API의 Search Grounding 기능 활용:
- `gemini-2.0-flash` 모델 + Google Search 연동
- 실시간 웹 검색 결과 기반 응답 생성

### 4.3 REQ-003: Fallback LLM (GPT-4o-mini)

#### 4.3.1 개요

| 항목 | 내용 |
|------|------|
| 요구사항 ID | REQ-003 |
| 우선순위 | 🟡 P1 (High) |
| 복잡도 | Medium |
| 예상 공수 | 3시간 |

#### 4.3.2 문제점

- 모든 핵심 노드가 Claude API에 의존 (4개 노드)
- Claude API 장애, Rate Limit, 크레딧 소진 시 전체 워크플로우 실패
- 대체 수단 없음

#### 4.3.3 해결 방안

- Claude API 실패 시 OpenAI GPT-4o-mini로 자동 전환
- 동일 프롬프트 구조 유지 (API 형식만 변환)

#### 4.3.4 Fallback 대상 노드

| 노드 | Fallback 노드 |
|------|--------------|

##### 신규 발행 시
```javascript

  version_id: versionId,
  content_id: contentId,

```

##### 변경 감지 시 (Daily Check)
```javascript
// 1. Notion에서 현재 콘텐츠 가져오기
const currentContent = await getNotionPageContent(pageId);
const currentHash = md5(currentContent);

// 2. 저장된 해시와 비교
const storedVersion = await getLatestVersion(contentId);

if (currentHash !== storedVersion.content_hash) {
  // 3. 새 버전 생성
  const newVersion = storedVersion.version + 1;

  // 4. 이전 버전 is_current = false
  await updateVersion(storedVersion.version_id, { is_current: false });

  // 5. 새 버전 레코드 생성
  await createVersionRecord({
    version_id: `${contentId}-v${newVersion}`,
    content_id: contentId,
    version: newVersion,
    change_type: 'update',
    change_summary: 'Content modified (detected)',
    created_by: 'manual',
    is_current: true,
    snapshot: currentContent,
    content_hash: currentHash
  });

  // 6. Slack 알림
  await notifyContentChange(contentId, newVersion);
}
```

##### 롤백 시 (수동)
```javascript
// 1. 목표 버전의 snapshot 가져오기
const targetVersion = await getVersion(contentId, targetVersionNumber);

// 2. Notion 페이지 업데이트
await updateNotionPage(pageId, targetVersion.snapshot);

// 3. 새 버전으로 기록 (rollback)
await createVersionRecord({
  version: currentVersion + 1,
  change_type: 'rollback',
  change_summary: `Rolled back to v${targetVersionNumber}`,
  snapshot: targetVersion.snapshot
});
```
